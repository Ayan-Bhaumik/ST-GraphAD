ST-GraphAD: Spatio-Temporal Graph Neural Network for Network Intrusion Detection on UNSW-NB15

Ayan Bhaumik
Independent Researcher
mrayanbhaumik@gmail.com  •  connect@ayanbhaumik.in

Abstract

Network intrusion detection systems (NIDS) increasingly face multi-stage attacks that manifest not as isolated anomalous flows but as evolving communication patterns among network entities. Flow-based and signature-based detectors evaluate connections independently and therefore cannot represent this relational structure. We propose ST-GraphAD, a spatio-temporal graph neural network that models network communication as a sequence of dynamic attributed graphs and jointly learns spatial communication structure and temporal attack evolution. Because the UNSW-NB15 CSV release omits explicit IP addresses, graphs are constructed with nodes derived from protocol–service–state tuples and edges corresponding to observed flows; this substitution is treated as an explicit, disclosed limitation rather than a hidden assumption. A three-layer graph convolutional network (GCN) encodes spatial structure within each time window, and a two-layer, four-head temporal attention module models dependencies across a sliding sequence of five graph snapshots. The network is trained end-to-end with a combined graph-level and node-level cross-entropy objective, using node-level validation AUC-ROC for early stopping and model selection to avoid degenerate graph-level metrics caused by class imbalance.

On UNSW-NB15, with the training CSV split into 85% training and 15% validation partitions, the official test CSV held out for final evaluation, preprocessing transformations fitted on the training partition only, and evaluation repeated over five random seeds, ST-GraphAD attains 0.657 ± 0.078 node-level AUC-ROC and 0.858 ± 0.021 F1-score, compared with 0.612 ± 0.030 AUC and 0.836 ± 0.013 F1 for a static GCN baseline trained under identical conditions. The mean AUC improvement is 4.5 percentage points absolute. ST-GraphAD also attains a mean recall of 0.939 ± 0.037 against 0.889 ± 0.023 for GCN, a 5.0 percentage-point absolute improvement. The larger standard deviation of ST-GraphAD (AUC std 0.078 vs. 0.030) indicates greater sensitivity to initialization; the observed improvement is therefore not claimed to be statistically established without further testing. Graph-level evaluation is degenerate under this dataset's class distribution (approximately 88% of nodes in the temporal graphs are attack-labeled, so almost every snapshot receives the majority-vote label "Attack"), yielding AUC = 0.00 for both models; we report this explicitly as an artifact of the label construction rather than a model failure, and treat node-level detection as the primary task throughout. We report computational cost, discuss the pseudo-node construction limitation, and identify key gaps for future work.

Keywords: Network Intrusion Detection, Graph Neural Networks, Spatio-Temporal Modeling, UNSW-NB15, Temporal Attention

1. Introduction

Network intrusion detection remains a critical cybersecurity challenge. The UNSW-NB15 dataset, created by the Australian Centre for Cyber Security, represents modern network traffic with nine attack categories: Generic, Exploits, Fuzzers, DoS, Reconnaissance, Analysis, Backdoors, Shellcode, and Worms. Traditional approaches treat each network flow independently, missing the relational context between communicating entities.

Network traffic naturally forms a graph structure:
- Nodes: IP addresses, ports, protocols (or proxy representations thereof)
- Edges: Communication flows between entities
- Temporal dynamics: Evolving communication patterns over time

Graph Neural Networks (GNNs) can exploit this structure, but static GNNs ignore temporal evolution. Attack patterns often manifest as temporal sequences—reconnaissance followed by exploitation, or multi-stage lateral movement. We propose ST-GraphAD to capture both spatial and temporal dimensions.

Contributions

1. Graph Construction Pipeline: Converts UNSW-NB15 network flows into attributed graphs with pseudo-nodes (protocol-service-state tuples) and communication edges, with explicit documentation of the IP-address limitation.
2. ST-GraphAD Architecture: Combines a 3-layer GCN spatial encoder with a 2-layer, 4-head temporal attention module over sliding windows of 5 graph snapshots.
3. Rigorous Experimental Protocol: The original training CSV is split 85/15 into training/validation; the official test CSV is held out; preprocessing is fitted only on the training partition; node-level validation AUC drives model selection; evaluation is repeated over five seeds with mean±std reporting.
4. Comprehensive Evaluation: Node-level AUC-ROC, F1, Precision, Recall on the untouched official test set; graph-level results reported with explicit caveats; computational complexity analysis; ablation study planned and documented.

2.4 Research Gap

Existing graph-based NIDS work predominantly uses static graphs, discarding temporal information critical for multi-stage attacks. Temporal GNNs (TGAT, TGN) have been applied to social networks and recommender systems but rarely to network intrusion detection with proper train/val/test splits and node-level evaluation. Furthermore, many studies report inflated results due to data leakage (preprocessing on combined data), test-set validation, or degenerate graph-level metrics from class imbalance.

3. Dataset and Problem Formulation

3.1 UNSW-NB15 Dataset

The UNSW-NB15 dataset contains network flows with 45 features per flow, including duration, protocol, service, state, packet/byte counts, and derived features (connection counts, time-to-live, etc.). The label column indicates normal (0) or attack (1); attack_cat specifies one of nine attack categories.

3.2 Data Preprocessing

Categorical features (proto, state, service, attack_cat) are encoded with LabelEncoder. Numerical features (34 continuous columns) are scaled with StandardScaler. Critically, all encoders and scalers are fitted exclusively on the training partition (149,039 flows) and applied to validation and test partitions without refitting, preventing preprocessing leakage.

3.3 Graph Construction

Node Definition

The UNSW-NB15 CSV release does not provide explicit source/destination IP addresses. We construct pseudo-nodes from categorical combinations:

srcip = proto + '_' + service + '_src'
dstip = state + '_' + service + '_dst'

This means each unique (protocol, service, role) tuple becomes a node. Multiple real hosts sharing the same tuple collapse to a single pseudo-node—a known limitation (§8).

Edge Definition

Each network flow creates an undirected edge between the corresponding source and destination pseudo-nodes. Edge attributes (packet counts, byte counts, duration, flags) are not currently used as features; this is future work.

Node Features (28-dimensional)

Per-node features are aggregated statistics over incident flows in each time window:
[mean_sbytes, mean_dbytes, mean_spkts, mean_dpkts, mean_sload, mean_dload, mean_dur, mean_sttl, mean_dttl, mean_sloss, mean_dloss, proto_mode, state_mode, service_mode, src_mean_sbytes, src_mean_dbytes, ..., dst_mean_sloss, dst_mean_dloss]

3.4 Temporal Graph Sequences

Flows are split into pseudo-temporal windows of 1000 flows each (by row order in the CSV, not real timestamps). Each window produces a graph snapshot Gᵢ = (V, Eᵢ, Xᵢ). A sliding window of length L=5 forms a sequence S = [G_{t-4}, ..., G_t] for training. We note this is a pseudo-temporal ordering; no real timestamps are available in the CSV release.

3.5 Formal Problem Definition

Given a sequence of L consecutive graph snapshots S = [G_{t-L+1}, ..., G_t], predict the node-level anomaly label vector ŷ_t ∈ [0,1]^{|V_t|} for the most recent snapshot G_t, where ŷ_{t,v} ≈ 1 indicates node v is involved in malicious communication. The graph-level label for S is defined as majority vote over nodes in G_t: y_S = 𝟙[mean(y_t) > 0.5].

4. Proposed ST-GraphAD Framework

4.1 Overall Architecture

ST-GraphAD processes a temporal sequence of L graph snapshots S = [G_1, ..., G_L] through three stages:

1. Spatial Encoder (shared across windows): 3-layer GCN → per-window node embeddings H^{(l)} ∈ ℝ^{|V_l| × d}, d=128.
2. Temporal Encoder: 2-layer Multi-Head Self-Attention (4 heads, d=128) with positional encoding, applied over the sequence of padded node embeddings → temporally enhanced embeddings H̃_L for the last window.
3. Detection Heads: (a) Graph-level: MLP(MeanPool(H̃_L)) → 2-class logits; (b) Node-level: MLP(H̃_L) → per-node 2-class logits.

4.2 Spatial Graph Encoder (GCN)

The GCN encoder follows Kipf & Welling (2017). For layer ℓ = 1...L:

H^{(ℓ+1)} = σ(D̃^{-1/2} Ã D̃^{-1/2} H^{(ℓ)} W^{(ℓ)})

where Ã = A + I (adjacency with self-loops), D̃ = degree matrix of Ã, L = 3 layers, hidden = 128, dropout = 0.5, batch norm after each layer except the last.

4.3 Temporal Encoder: Multi-Head Attention

Node embeddings from each window are padded to N_max = max_l |V_l|, forming a tensor X ∈ ℝ^{L × N_max × d}. A mask M ∈ {0,1}^{L × N_max} indicates valid nodes. Standard multi-head attention is applied:

Q, K, V = X W_Q, X W_K, X W_V
Attention(Q,K,V) = softmax(QK^⊤/√d_k) V
MultiHead = Concat(head_1,...,head_h) W_O

Two attention layers with residual connections and layer normalization. The output for the last window (H̃_L) is used for classification. The multi-head architecture provides capacity to model different temporal dependencies; however, head specialization was not quantitatively evaluated in the present study.

4.4 Detection Heads

Graph-level: MLP(MeanPool(H̃_L)) with hidden layer d/2, ReLU, dropout → 2 logits.
Node-level: MLP(H̃_L) with hidden layer d/2, ReLU, dropout → per-node 2 logits.

4.5 Loss Function

Combined graph-level and node-level cross-entropy:

L = L_graph + λ L_node, λ = 0.5
L_graph = CE(z_graph, y_S)
L_node = (1/N_L) Σ_v CE(z_node,v, y_{L,v})

4.6 Training Procedure

- Optimizer: Adam (lr=10⁻³, weight decay=5×10⁻⁴)
- Scheduler: ReduceLROnPlateau (factor=0.5, patience=10, mode=max on validation node-level AUC-ROC)
- Gradient clipping: ||∇||₂ ≤ 1.0
- Early stopping: Patience 10 on validation node-level AUC-ROC
- Max epochs: 50
- Sequence length: L=5
- Max training sequences/epoch: 200 (randomly sampled)
- Device: CPU (Apple M4, 16 GB RAM)

6. Results

6.1 Graph-Level Classification (Degenerate)

Model | AUC-ROC | F1 | Precision | Recall
---|---|---|---|---
GCN-only | 0.00 | 1.00 | 1.00 | 1.00
ST-GraphAD | 0.00 | 0.00 | 0.00 | 0.00

Explanation: The graph label is y_S = 𝟙[mean(y_t) > 0.5]. With approximately 88% attack nodes in temporal graphs, almost every graph snapshot receives label 1 ("Attack"). The classifier trivially learns to predict "Attack" always. AUC=0.00 reflects single-class ground truth, not model failure. Graph-level F1/Precision/Recall of 1.00 likewise reflect trivial majority prediction, not model quality. Graph-level metrics are not meaningful for this dataset/task formulation and are not used for model selection.

6.2 Node-Level Anomaly Detection (Primary Task)

The five-seed aggregate below is the principal result of this study. Values are mean ± standard deviation over five random seeds (42, 123, 456, 789, 999), 50 epochs each, identical configuration.

| Model | AUC-ROC | F1 | Precision | Recall |
|-------|---------|-----|-----------|--------|
| GCN-only | 0.612 ± 0.030 | 0.836 ± 0.013 | 0.789 ± 0.015 | 0.889 ± 0.023 |
| ST-GraphAD | 0.657 ± 0.078 | 0.858 ± 0.021 | 0.791 ± 0.022 | 0.939 ± 0.037 |

Absolute improvements of ST-GraphAD over GCN (mean to mean):
- AUC-ROC: +4.5 percentage points (0.657 − 0.612 = 0.045)
- F1: +2.2 percentage points (0.858 − 0.836 = 0.022)
- Precision: +0.2 percentage points (0.791 − 0.789 = 0.002)
- Recall: +5.0 percentage points (0.939 − 0.889 = 0.050)

Interpretation: ST-GraphAD shows higher mean node-level AUC, F1, and recall than the static GCN baseline. However, the larger standard deviation of ST-GraphAD (AUC std 0.078 vs. 0.030; recall std 0.037 vs. 0.023) indicates greater sensitivity to initialization, so the observed improvement should not be interpreted as universally established without further statistical testing. No statistical significance test was performed in this study.

Training is driven by node-level validation AUC-ROC for early stopping. 6.6 Computational Complexity

Runtimes below are from the final 5-seed, 50-epoch experiment (128 hidden channels, 3 GCN layers).

Model | Parameters | Train Time (50 ep, seed=42) | Peak CPU Memory
---|---|---|---
GCN-only | ~180K | ~10 sec | ~300 MB
ST-GraphAD | ~4.2M | ~86 sec | ~1.2 GB

ST-GraphAD requires ~23× more parameters and ~4× more memory than the GCN baseline, primarily due to the temporal attention module's projection matrices and the padded sequence tensor (L × N_max × d). Training time is ~8.6× slower (50-epoch run). For deployment, model distillation or attention pruning may be necessary.

Note: A separate exploratory run used a larger configuration (256 hidden channels, 4 GCN layers, 200 epochs) producing different absolute runtimes (GCN ~114 s, ST-GraphAD ~593 s). Those values belong to a different configuration and are not used as the headline computational numbers above.

6.7 Attack-Category Analysis

Per-attack-category node-level evaluation was not implemented in the current study and remains future work. The node labels are binary (attack vs. normal) and the attack_cat field is only available at flow level, which is lost during node aggregation. We do not claim superior performance on Generic, Exploits, Fuzzers, DoS, Reconnaissance, Analysis, Backdoors, Shellcode, or Worms individually.

7. Discussion

7.1 Why Temporal Modeling May Help

The positive mean AUC and recall improvement from temporal attention (multi-seed) is consistent with the model's design: conditioning the current window's node representations on preceding windows. In network traffic, attack stages may leave temporal footprints:

- Reconnaissance → Exploitation: A node that appeared in a scanning window (high out-degree, diverse destinations) and then initiates a suspicious connection in the current window may receive higher anomaly scores.
- Periodic beaconing: Nodes with recurring communication patterns at regular intervals across windows may be flagged by the attention mechanism.
- Lateral movement: A previously benign node that suddenly communicates with a compromised node in the current window may get elevated scores through attention to the compromised node's history.

These are design rationales and qualitative expectations; the present study does not contain case-level or attention-based evidence establishing that ST-GraphAD detects any specific multi-stage attack sequence.

7.2 Interpretation of Attention

Attention weights A ∈ ℝ^{L×L} (aggregated over heads and nodes) show the model's temporal focus. We did not perform quantitative attention analysis (entropy, head specialization metrics) in this study. Claims about which temporal patterns particular heads capture are not supported by experiments in this work and remain future work.

7.3 Practical Cybersecurity Implications

1. Node-level scoring for triage: ST-GraphAD outputs per-node anomaly probabilities. Security analysts can prioritize investigation of high-scoring IPs/hosts.
2. Temporal context for threat hunting: The temporal attention module provides a mechanism to attribute the current alert to historical windows, enabling timeline reconstruction (qualitative; not quantitatively validated here).
3. Inductive generalization: The GCN encoder is inductive—it can embed unseen nodes (new pseudo-IP combinations) without retraining, supporting streaming deployment.
4. CPU compatibility: The model trains and runs on CPU (no GPU required), lowering operational barriers.

7.4 Failure Cases

Failure Mode | Cause | Mitigation (Future)
---|---|---
Single-flow attacks (e.g., volumetric DoS) | No temporal history; one window | Hybrid: combine ST-GraphAD with per-flow statistical detectors
Encrypted traffic | Payload features unavailable; flow stats may be insufficient | Incorporate TLS fingerprinting (JA3), packet timing side-channels
Graph-level label degeneracy | ~88% attack ratio → all graph labels "Attack" | Use node-level metrics only; graph-level regression
Pseudo-node collision | Multiple real IPs → same pseudo-node | Parse PCAP for real IPs; use heterogeneous graphs

8. Limitations and Threats to Validity

8.1 Internal Validity Threats

# | Threat | Severity | Status / Mitigation
---|---|---|---
1 | Pseudo-node construction | High | Unfixed. Nodes are protocol-service-state tuples, not real IPs. Multiple real hosts collapse. Graph structure is a proxy.
2 | Pseudo-temporal ordering | High | Unfixed. Windows derived from CSV row order, not real timestamps; may split/merge attack campaigns.
3 | Fixed 1000-flow windows | Medium | Unfixed. Arbitrary granularity; no timestamp alignment.
4 | No per-attack-category evaluation | Medium | Unfixed. Binary node labels only; attack_cat lost during aggregation. Flagged as gap.
5 | No attention visualization | Medium | Unfixed. Claims about attention interpreting attack stages are qualitative/unverified.
6 | Class imbalance at graph level | High | Mitigated. Graph-level metrics reported with explicit caveat; node-level AUC used for all model selection.
7 | Preprocessing leakage | High | Mitigated. LabelEncoder/StandardScaler fit on training partition only, applied to val/test without refitting.
8 | Single-class AUC handling | Medium | Fixed. AUC = None (not 0.0) when a partition contains only one class; NaN handled in scheduler.
9 | Variance across runs | Medium | Addressed. Five-seed evaluation with mean±std reported.
10 | Flow partition / pseudo-node overlap | Medium | See §8.4. Pseudo-node identifiers may recur across partitions; this is distinct from flow-level overlap and is not automatically leakage.

8.2 External Validity Threats

# | Threat | Discussion
---|---|---
1 | UNSW-NB15 CSV limitations | Real network traffic has IPs, ports, timestamps. Our graph construction is dataset-specific.
2 | Single dataset | Results may not generalize to CICIDS2017, CSE-CIC-IDS2018, or enterprise traffic.
3 | Binary labels only | Real NIDS often needs multi-class (attack category) or severity scoring.
4 | CPU-only training | MPS/CUDA errors prevented GPU training. Larger models/hyperparameter searches were infeasible.
5 | Higher variance of ST-GraphAD | ST-GraphAD shows AUC std 0.078 vs GCN 0.030. Sensitivity to initialization is a deployment concern.

8.3 Construct Validity Threats

# | Threat | Discussion
---|---|---
1 | Node label derivation | y_v = max(source flows, dest flows) labels a node "Attack" if any incident flow is attack. This may over-label benign nodes that happen to receive one malicious packet.
2 | Graph label = majority vote | With ~88% attack nodes, this is degenerate. Alternative: graph-level regression (predict attack proportion).
3 | Sequence label = last window label | Assumes the last window is representative of the sequence.

8.4 Note on Partition Independence and Pseudo-Node Identifiers

The flow records are partitioned into training, validation, and official test sets by flow index, and a sanity check confirms no flow index is shared across partitions. However, the same pseudo-node identifier (constructed from categorical attributes) may legitimately occur across partitions because multiple flows—even across splits—can share the same protocol/service/state tuple. This identifier recurrence is not equivalent to overlap of the underlying flow records and must not be described as data leakage. The relevant leakage-control guarantee is that preprocessing transformations (LabelEncoder, StandardScaler) are fitted using training flows only and subsequently applied to validation and test data without refitting; no validation or test label is used for training, checkpoint selection, scheduler control, or early stopping.

9. Conclusion and Future Work

9.1 Conclusion

We presented ST-GraphAD, a Spatio-Temporal Graph Neural Network for network intrusion detection on the UNSW-NB15 dataset. ST-GraphAD constructs dynamic attributed graphs from flow records (using a documented pseudo-node heuristic necessitated by the CSV release format), encodes spatial communication patterns via a 3-layer GCN, and models temporal attack evolution via a 2-layer, 4-head attention mechanism over sliding windows of 5 graph snapshots.

On node-level anomaly detection—the primary task—under the corrected protocol (training CSV split 85/15 for train/validation, official test CSV held out, preprocessing fitted on training only, node-level validation AUC for early stopping and model selection, five-seed evaluation), ST-GraphAD achieves 0.657 ± 0.078 AUC-ROC and 0.858 ± 0.021 F1, compared to a static GCN baseline of 0.612 ± 0.030 AUC and 0.836 ± 0.013 F1. The mean AUC improvement is 4.5 percentage points absolute; the mean recall improvement is 5.0 percentage points absolute. ST-GraphAD exhibits higher variance (AUC std 0.078 vs 0.030), so the improvement is reported as a measured mean difference, not as a statistically established effect. Graph-level evaluation remains confounded by class imbalance (~88% attack nodes in temporal graphs), yielding AUC=0.00 for both models—a dataset artifact, not a model failure.

The framework trains in roughly 10–90 seconds per seed on CPU (Apple M4, 16 GB), requires ~1.2 GB memory, and is released as open-source PyTorch Geometric code.

9.2 Future Work

1. Real IP-based graph construction: Parse PCAP files to extract true source/destination IPs and ports, eliminating the pseudo-node heuristic.
2. Continuous-time temporal GNNs: Adopt TGN or CAW for event-level temporal modeling, removing fixed-window discretization.
3. Heterogeneous graphs: Model IPs, ports, protocols, and services as distinct node types with relation-specific edges.
4. Self-supervised pre-training: Masked flow reconstruction or contrastive learning on unlabeled traffic to reduce labeled data needs.
5. Per-attack-category evaluation: Implement multi-class node classification and category-wise AUC/F1 reporting.
6. Attention interpretability: Systematic attention visualization, head ablation, and entropy analysis for analyst-facing explanations.
7. Online/incremental learning: Streaming graph updates without full retraining.
8. Adversarial robustness: Evaluate against graph-structure and feature-space evasion attacks.
9. Statistical evaluation: Paired significance testing (e.g., McNemar, Wilcoxon) across seeds to establish whether the observed improvement is significant.
